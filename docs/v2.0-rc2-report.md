## 3. 修复

### P-3 原子写入（提交 `19341f7`）

- `writeJSON` 与 `writeFileAtomic` 合并为 `atomicWrite`：临时文件 `<目标>.<pid>.<8 位随机十六进制>.tmp`，`wx` 打开（重名就失败，不会覆盖别人的文件）→ 写入 → fsync → rename。
- 任何一步失败：只删**这一次自己创建的**临时文件，**从不删除 / 截断目标文件**（目标保持写入前的完整内容）；错误照常抛给调用方（接口返回 500）。
- 启动清理 `sweepStaleTmp()`：只扫描本程序写这类文件的目录（`data/`、`config/`、`spaces-guard/`、`wallpapers/`、`backup/<用户>/`、`icons/<用户>/`；`cache/` 仍由原来的缓存清理负责），只删**同时满足**以下条件的文件：文件名完全匹配 `<名字>.<pid>.<8 位十六进制>.tmp`；是普通文件；修改时间超过 1 小时；pid 已不在运行（`kill(pid, 0)` 为 ESRCH；EPERM 视为在运行）——pid 等于本进程时（容器里常见），还要求修改时间早于本次启动且不在本进程正在写的列表里。每删一个记一行 `stale tmp removed <相对路径>`。

### P-2 回滚写保护旁路一致性（提交 `52ac812`）

- **绑定版本 + 指纹**：旁路文件新增 `fmt: 2`、`h`（该版本 `data` 的 sha256 指纹，与配置 `hist` 里的 `h` 同一算法）；V2 每次写配置，`hist` 里新版本的条目带 `g: 2`。V1.1 / RC.1 的 `writeConfig` 原样复制旧 `hist` 条目（已核对两者代码都是 `cur.hist.slice()`），所以标记会保留。
- **写入失败不静默**：配置照常保存（已写好），但：删掉旧旁路（磁盘满时删除照样成功；目录不可写时删不掉，由下面的校验拦住）；日志 `ERROR spaces guard write failed <用户> <错误码> …`；这次保存的响应带 `guardWarning: "spaces_guard_write_failed"`；管理员 `/api/health` 新增 `guard: {ok, issues:[{user, kind, at, error, invalidated}]}`（未登录 / 普通账户看不到）。该账户下次旁路写成功或重启自愈后清除。没有界面改动（前端不显示新字段）。
- **找回前校验**（`guardRecover`）：原有条件之外，要求旁路「对得上」配置历史——旁路版本在 `hist` 里、指纹一致（旧格式旁路没有指纹，跳过这一项）、`hist` 里没有比它新的 `g: 2` 版本。校验不过 → 日志 `spaces guard: stale …`、管理员诊断 `kind: "stale"`，不用旁路；改为在快照环里找「`hist` 里最新的 V2 版本」且版本号 + 指纹都一致的那一份，用它的空间；也找不到 → 不找回（日志 `spaces guard: skipped … not in the backup ring`）。同一账户同一版本的这两类日志只记一次（读取配置时也会检查）。
- **删掉的空间不会复活**：V2 最后的状态是 `[]`（删光）或没有 `spaces`（恢复默认）时，不论来源是旁路还是快照环，都不找回。
- **启动自愈**（`guardHeal`，启动迁移时每个账户执行一次）：最后一次由 V2 写入的配置，旁路缺失 / 损坏（半截 JSON）/ 旧格式（RC.1）/ 版本或指纹对不上 → 按当前配置重写旁路（保留 `recovered` 提示信息），日志 `spaces guard: healed <用户> v<版本> (<原因>)`。**只写旁路，不改配置文件**（测试逐字节核对）。
- 写入顺序保持「先配置、后旁路」：配置写失败时旁路不动（旧旁路对应旧版本，仍然一致）；旁路写失败时由上面的作废 + 校验兜底。

### P-1 cookie 名前缀（提交 `a14f01f`）

- 环境变量 `NOCTURNE_COOKIE_PREFIX`（默认 `nocturne_`）→ 会话 `<前缀>sid`、已知设备 `<前缀>dev`；登录、退出、设备识别、`/api/health` 判断管理员都用同一组名字。空值等于默认。
- 取值规则：字母、数字、`_` `.` `-`，1–32 字符，以字母或数字开头；因此 `__Host-` / `__Secure-` 一律拒绝（它们要求每个响应都带 `Secure`，本程序只在 HTTPS 请求上加 `Secure`，用了会让 HTTP 下登录静默失效），报错信息单独说明这一点。不合法 → 启动时打印 `配置错误：NOCTURNE_COOKIE_PREFIX …` 并以退出码 2 退出，不写任何数据、不监听端口。
- `HttpOnly` / `SameSite=Lax` / `Path=/` / `Secure`（仅 HTTPS / 可信代理转发的 HTTPS）逻辑不变。启动日志多一项 `cookies=<会话名>/<设备名>`。
- 文档：README 环境变量表、`docker-compose.yml` 注释示例；`tools/v2test/deploy.sh` 生成的测试 compose 设置 `NOCTURNE_COOKIE_PREFIX=nocturne_v2test_`，提示文字说明 rc.2 起生效、rc.1 镜像仍需换主机名；`tools/v2test/README.md` 第 3 节同步。改了前缀的实例，已有设备需要重新登录一次（旧名字的 cookie 不再被识别）。

## 6. RC.1 → RC.2 兼容

测试 `test/rc1-compat.test.js`：RC.1 代码按 blob SHA 从 git 取出（远程 `2ee0983` 的 `server.js` / `package.json` / `public/*`，已用 GitHub API 逐个核对 blob），与 RC.2 在同一个 data 目录上来回切换：

1. RC.1：初始化管理员、上传图标、保存带空间的配置、上传壁纸、建第二个账户。
2. RC.2 启动：RC.1 发的会话 cookie 继续有效（默认 cookie 名不变）；密码登录；配置内容相同、读取不升版本、**配置文件逐字节不变**、启动不改 `users.json`；图标 / 壁纸字节一致；第二账户可登录；快照环可读；旁路由旧格式自愈为 `fmt: 2`（版本 = 配置版本），`guard.ok = true`。RC.2 保存一次：`hist` 新条目带 `g: 2`。
3. 回滚 RC.1：RC.2 期间的会话有效；读到 RC.2 写的空间；图标 / 壁纸正常；RC.1 照常保存，并原样保留 `hist` 里的 `g: 2`；RC.1 把旁路写回旧格式（预期，RC.2 能读）。
4. RC.1 → V1.1「用本机版覆盖」丢掉空间 → 直接升 RC.2：用 RC.1 写的旧格式旁路找回 RC.1 最后的空间（`source: guard`）。
5. 再回滚 RC.1：读到找回后的配置和 `recovered` 提示。

**新增的文件 / 字段**（都向后兼容，RC.1 / V1.1 忽略不认识的字段）：

- `data/spaces-guard/<用户>.json`：新增 `fmt: 2`、`h`（sha256 十六进制）。RC.1 读它只用 `version` / `spaces` / `spacesVersion` / `recovered`；RC.1 下次写会去掉这两个字段，RC.2 启动时自愈补回。
- `data/config/<用户>.json` 的 `hist[]` 条目：V2 写的版本多一个 `g: 2`。RC.1 / V1.1 只读 `v` / `h`，并原样复制旧条目。
- 新环境变量 `NOCTURNE_COOKIE_PREFIX`（不设 = 原来的 cookie 名）。
- 保存响应新增可选字段 `guardWarning`；管理员 `/api/health` 新增 `guard`。
- 没有新目录、没有新数据文件；`users.json` / `sessions.json` / 备份 / 图标 / 壁纸格式不变。

**风险 / 行为变化**：

- 找回比 RC.1 更保守：回滚期间 V1.1 保存超过约 19 次后，旁路对应的版本已滚出配置历史（只留最近 20 个），无法校验 → 不自动找回（空间仍可在「恢复较早的版本」里手动找）。RC.1 在这种情况下会照旧找回（也就可能找回过期的空间）。这是为「删掉的空间绝不复活」做的取舍。
- 旧格式旁路（RC.1 写的）没有指纹：只能校验「版本在历史里、之后没有 RC.2 写的版本」。如果 RC.1 自己曾经旁路写入失败（RC.1 日志里会有 `spaces guard write <用户> …`），然后 RC.1 → V1.1 → 直接升 RC.2，这一种路径仍可能用到 RC.1 的过期旁路。RC.2 启动过一次（自愈）之后就不再有这个风险。部署 RC.2 前可以 `grep "spaces guard write" ` 一下 RC.1 的容器日志确认。
- 改了 `NOCTURNE_COOKIE_PREFIX` 的实例：所有设备需要重新登录，「已知设备」也要重新建立（登录限速对新设备按普通规则）。生产实例不需要设置它。
- RC.2 启动时会重写旧格式旁路（每个账户一次，只写 `spaces-guard/`），并可能删除符合条件的过期临时文件（只限第 3 节的严格规则）。
