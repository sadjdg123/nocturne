# V2.2.1 · 运行环境升级到 Node 24 LTS

基于 main `00590d9`（V2.2.0）。只升级运行底座和 CI 工具版本；`server.js`、`auth-store.js`、`public/` 与数据格式、接口、认证、同步、空间语义、静态资源 URL / 内容全部不变。

## 为什么升级

- Node 22（Jod）已进入维护期，官方计划 2027-04 停止维护；Node 24（Krypton）是长期支持版，维护到 2028-04。以 nodejs.org 发布索引为准（2026-11-06 查询：24.22.2 / 22.23.4 均为 LTS）。
- GitHub 已把 Actions 运行时迁到 Node 24；旧版动作会出现强制切换提醒。

## 更新

| 位置 | 之前 | 之后 |
|------|------|------|
| `Dockerfile` 基础镜像 | `node:22-alpine` | `node:24-alpine`（官方镜像含 amd64 / arm64） |
| `tools/engineering/runner.Dockerfile` | `node:22-alpine` | `node:24-alpine` |
| `docker.yml` 测试用 Node | 22 | 24 |
| `actions/checkout` | v4 | v7 |
| `actions/setup-node` | v4 | v7 |
| `docker/setup-qemu-action` / `setup-buildx-action` / `login-action` | v3 | v4 |
| `docker/metadata-action` | v5 | v6 |
| `docker/build-push-action` | v6 | v7 |
| `package.json` `engines.node` | `>=20` | `>=22`（Node 20 已停止维护；`probe-connection` 用例本来就要求 22+） |

动作升级只核对了本仓库实际用到的输入：全部仍存在、含义不变。setup-node v6 起“声明 `packageManager` 时自动开启 npm 缓存”与本仓库无关（没有该字段，也没有锁文件）；v7 去掉的虚拟 `NODE_AUTH_TOKEN` 只影响设置 `registry-url` 的工作流，本仓库未使用。`engineering-verify.yml` 使用固定 SHA 的动作，本次不动，后续单独回归。

镜像标签规则、`paths-ignore`、权限和“测试通过才构建”的顺序都不变。

## 验证

本地 Linux（root 用户，jsdom@24 与 CI 相同），同一台机器上对照：

| | 原版 V2.2.0 · Node 22.23.4 | 本分支 · Node 24.22.2 |
|---|---|---|
| `npm run check` | 通过 | 通过 |
| 全量 748 项 | 浅克隆下 7 失败 / 22 跳过 | 浅克隆下 6 失败 / 22 跳过（同一批） |
| 补全 Git 历史后重跑受影响的 5 个文件（102 项） | 101 / 102 | 101 / 102 |

- 浅克隆导致的失败与跳过（RC.1–RC.4 发布基线、RC.1 兼容数据）在补全历史后全部通过，两个版本结果一致；CI 本来就用 `fetch-depth: 0`。
- 剩余 1 项 `spaces-switcher` “全部: every icon item” 在两个版本上同样失败：用例会让服务器真实探测夹具里的 192.168.x / `.local` 地址，本机沙箱对这些地址立即拒绝，其中一项被判为“无法确认”，在线统计变成 `/ 6`。与本次升级无关，以 CI 结果为准。
- 另有 4 项“以 root 运行无法模拟目录不可写”的跳过，CI 以非 root 运行不受影响。
- 本地无 Docker 守护进程，双架构镜像构建由 PR 上的现有 CI 完成（PR 只构建不推送）。

## 升级与回滚

升级方式与以往相同：停写备份 → compose 改到新的固定镜像 → 健康 / 登录 / 空间 / 图片核验。数据目录无需迁移。回滚：compose 改回 V2.2.0 固定镜像 `sha-d0ff57d@sha256:4e7e17972635aa60a71c81871bfe5a15ca8f1129aeda05d2bf36eee22569120e` 即可。
