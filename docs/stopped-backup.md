# 停写完整备份：升级与灾备基准

热备份只是尽力检查变化：复制前、复制后、源 hash 核查后使用同一规则重新枚举文件和目录；增加、删除、改名或内容变化重试，最多三次。find/hash/cp/tar/gzip 失败不能产出成功归档。文件与空目录一并保存，归档格式仍为 1，包含中断认证事务材料。保留既有临时文件排除，但不排除 `.tmp` 结尾的目录，以免遗漏合法账户资产；控制字符路径失败关闭。仍无法证明持续写入时所有文件属于同一事务时刻。

正式升级、回滚与灾备基准使用以下流程；本轮未对 NAS 执行这些命令：

1. 操作者确认正确容器、唯一写入实例及挂载 DATA_DIR，记录当前提交、版本和镜像 digest。
2. 手工停止该实例，并通过 Container Manager 或 docker inspect 确认已停止；不让其它进程继续写 DATA_DIR。
3. `sh tools/backup.sh -o <独立备份目录> <DATA_DIR>`，不使用 --exclude-ring / --exclude-cache。手工停机后运行此命令不会自动启动服务，便于继续升级。
4. `sh tools/verify-backup.sh <归档>` 核验归档及 .sha256，再在隔离目录用 restore.sh 恢复；核对账户、配置、空间、图标、壁纸、旁路、环形及固定快照。若包含未完成认证事务，须先用修复版在隔离目录恢复并核验密码与会话。
5. 保存归档、侧车、测试记录、提交及镜像 digest，再由用户按另行批准的部署步骤继续。归档含密码哈希和会话，权限 600。

`--stop <容器>` 仍支持短暂停机后恢复原运行状态：先 inspect 原状态；原已停止则不调用 stop/start；只有确实停止原运行容器才启动。停止失败不备份；启动失败非零退出并明确区分“归档已验证”与“服务未恢复”。容器状态故障注入使用假命令；第二阶段另外停止真实隔离测试容器，使用其只读源卷与新空目标卷完成 BusyBox 备份/恢复演练。没有连接 NAS 或生产 Docker socket。

最终归档用硬链接独占发布，先安装已计算好的侧车，再发布归档；同名归档或侧车拒绝覆盖。暂存 tar、gzip 和内部校验完成前不会出现最终归档。磁盘需要源目录暂存、未压缩 tar 和压缩归档的额外空间；空间不足会失败清理，不能据此减少完整备份内容。

macOS sh/dash 及隔离 Alpine BusyBox 的实际完整备份/恢复已验证；Linux dash/BusyBox 沙盒工具套件各 51/51。DSM 宿主工具、真实磁盘满和断电仍需用户另行批准的隔离平台验收，不能从 Alpine 推定。备份成功行保留 `备份完成：<归档路径>` 的独立行契约，供 deploy.sh 使用；文件计数另行输出。
