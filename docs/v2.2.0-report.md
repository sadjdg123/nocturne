# V2.2.0 · 首页瘦身、长期缓存与 CSP

基于 main `4dac6f8`（V2.1.3 + 壁纸 ETag 缓存 / 图标背景色限制修复）。目标是让手机经外网（Cloudflare）打开首页时少下载、少往返；数据格式、接口、认证、同步逻辑、空间语义、默认 Cookie 名和界面外观 / 行为不变。

## 更新

- **首页拆分**：`index.html` 原有 5 段内联 `<style>`、11 段内联 `<script>` 原样移入 4 个静态文件，顺序与每段 IIFE 边界不变：
  - `app.css`（原 head 内样式，放在 `midnight.css` 之前）、`app-ui.css`（原 body 内样式，放在 `midnight.css` 之后，保持层叠顺序）；
  - `app.js`（核心 `window.App`，在 `nocturne.js` 之前）、`app-ui.js`（编辑、拖动、添加、状态、设置、命令面板、空间，在 `nocturne.js` 之后、`midnight.js` 之前）。
  - 首页只保留骨架和首帧前必须执行的两段内联脚本：`html[data-ui]`（仍在 `midnight.css` 之前）与后端启动脚本。
- **启动数据**：服务器不再注入可执行的 `<script>window.NOCTURNE=…</script>`，改为 `<script type="application/json" id="nocturne-boot">`（继续把 `<` 转义为 `<`），由启动脚本读成 `window.NOCTURNE`，其余代码不变。纯静态模式没有这个数据块，行为照旧。
- **长期缓存**：带 `?v=` 的静态文件改为 `public, max-age=31536000, immutable`；字体保持 immutable；`fonts.css`、`Sortable.min.js`、图标、manifest 等不带版本号的文件和 `index.html`（`no-store`）保持原策略。4 个新文件的 `?v=` 是内容 sha256 前 10 位，`test/csp.test.js` 强制校验；既有文件仍由 `test/cache-bust.test.js` 与发布基线约束“同 URL 必须同内容”。
- **CSP**：首页响应新增 `Content-Security-Policy`：
  `default-src 'self'; script-src 'self' <两段内联脚本的 sha256>; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: http: https:; connect-src 'self' data: blob: http: https:; font-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`。
  hash 由 `server.js` 按实际下发的内联脚本内容计算，改动内联脚本无需手工更新。`script-src` 不含 `'unsafe-inline'` / `'unsafe-eval'`；大量 `style="--h:…"` 内联样式属性保留 `'unsafe-inline'`。图片和连接放开 http(s)：项目图标、壁纸可以是任意 http(s) 地址，服务器没给结果时浏览器会直接探测项目地址；`data:` / `blob:` 用于旧版内嵌图片迁移和上传预览。
- **内联事件**：全仓库唯一的内联事件处理器（图标 `<img onerror="App.util._fail(this)">`）改为在 document 上用捕获阶段统一监听图片 `error`，失败后同样换成字母徽记并记住失败地址。

## 体积对比

本地 `server.js` 实测（gzip，与线上相同的压缩级别）：

| | V2.1.3（`4dac6f8`） | V2.2.0 |
|---|---|---|
| `index.html` 原始 | 240,732 B | 6,749 B |
| `index.html` 压缩后（每次打开都下载） | **67,817 B** | **2,524 B** |
| 首次打开：首页 + 全部脚本 / 样式（压缩后） | 154,002 B，12 个请求 | 153,934 B，16 个请求 |
| 再次打开（缓存超过一天） | 67.8 KB + 11 次重新校验 | 2.5 KB + 2 次重新校验（`fonts.css`、`Sortable.min.js`），13 个文件直接用缓存 |

首次打开总量基本不变（多 4 个请求，均可并行）；之后每次打开少下载约 65 KB，并省去 9 次重新校验往返。

## 验证

- 新增 `test/csp.test.js`：首页体积 / 只剩两段内联脚本 / 无内联 `<style>` / 加载顺序；4 个新文件 `?v=` 与内容一致；源码中无 `on*=` 内联处理器；首页 CSP 头（`script-src` 无 `unsafe-inline`，hash 与下发的内联脚本逐一对应）与 JSON 启动数据块；jsdom 运行后台页面并打开设置 / 编辑 / 添加 / 命令面板后 DOM 中没有 `on*` 属性或未放行的内联脚本，图标 `error` 事件仍换成字母徽记。
- `test/cache-bust.test.js` 缓存头用例改为：全部 `?v=` 引用 immutable；`fonts.css`、无版本或带其他查询参数的地址仍 1 天重新校验；ETag / 304 保留。
- 按文本检查前端接线的测试（`cmdrank`、`dock`、`netmode`、`status-action`、`status-label`）改为读取 `test/page-source.js`：`index.html` 加上它实际引用的本地脚本 / 样式，检查内容不变；`appearance` 仍直接检查 `index.html` 里 `data-ui` 段在 `midnight.css` 之前。自己用 JSDOM 加载页面的测试原本就从磁盘加载外部脚本，无需改动。
- 真实 Chromium（Playwright）在 CSP 下加载登录后页面、登录界面、经典外观和 `file://` 静态模式，并打开设置 / 编辑 / 添加 / 命令面板：`securitypolicyviolation` 为 0，资源加载报错与 V2.1.3 相同（仅离线环境的上游图标）。390×844 与 1440×900 两种视口、四种状态的截图与 V2.1.3 逐像素对比，差异不超过同版本两次截图之间的渲染噪声（只有时钟分钟不同）。

## 升级与回滚

由用户手动停写备份并固定新镜像升级，本轮不操作 NAS 或 Cloudflare。升级后第一次打开会按新 URL 下载 4 个新文件；之后带 `?v=` 的文件一年内不再请求。回滚：把 compose 里的镜像改回 V2.1.3 / `sha-4dac6f8` 等历史固定镜像即可，旧版本的 URL 与内容约束未变，浏览器缓存不会串版本。
