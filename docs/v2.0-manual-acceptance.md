# 夜曲 Nocturne V2.0 RC · 人工验收清单

历史清单基于 `2.0.0-rc.1`；当前候选、镜像及发布报告统一见 [开发交接版本表](HANDOFF-CODEX.md#01-版本--镜像--digest)。人工验收须同时记录完整源码 SHA/镜像 digest，不能只看 `/api/health` 的版本。

用户已确认 RC.4 在真实 NAS 部署成功、iPhone Safari 正常、重启数据保留及健康检查正常；下方历史逐项勾选仍需操作者按具体设备证据填写。本轮修复版的 Linux/Docker 工程证据见 `phase2-engineering-report.md`，不能据此勾选修复版真机、DSM 或真实断电验收。
勾选方法：做完一步、结果与「预期」一致就把 `[ ]` 改成 `[x]`；不一致请在该行后面写下实际看到的现象（截图更好），不要勾选。

> 约定：下文「夜曲地址」指测试部署的地址（第 6 节的套件会打印推荐网址，例如 `http://<NAS主机名>.local:8089`；**主机名要与生产站不同，并用无痕窗口打开**）。
> 测试期间**不要动正在使用的生产容器和它的 `data/`**；任何真实 NAS 操作须用户另行批准。

## 6. 并行测试部署（套件 `tools/v2test/`）

> **状态：套件已就绪，等你在 NAS 上运行。** Hark 没有 NAS 的访问权限，所有命令都由你在 SSH 里执行；套件在沙盒里用 dash / busybox sh + 假 docker + 真实 server.js 做过端到端测试（见 `docs/v2.0-rc-report.md` 第 14 节）。

目的：在**不影响正在使用的生产版本**（容器 `nocturne`，端口 8088，数据 `/volume1/docker/nocturne/data`）的前提下，用一份**经过校验的备份恢复出来的副本**试用 V2 RC。

**套件做什么 / 不做什么**（详见 `tools/v2test/README.md`）

- 预检：从 `docker inspect nocturne` 自动找到生产 data；测试数据固定在 `/volume1/docker/nocturne-v2test/data`；两者相同或互相包含就拒绝；8089 必须空闲（`docker ps` 端口映射 + `ss` / `netstat`）；同名容器 `nocturne-v2test` 若不是套件创建的就拒绝；自动检测默认路由网卡的内网 IP（RFC1918）。
- 并行测试固定镜像以 `tools/v2test/lib.sh` 的 `IMAGE_TAG` / `IMAGE_DIGEST` 为准（对应开发交接版本表），拉取后核对 RepoDigest；GHCR 拒绝时打印 `docker login`（只勾 `read:packages` 的 PAT）说明，套件不保存任何令牌。
- 数据：`tools/backup.sh` **热备份（不停生产容器）** → `verify-backup.sh` → `restore.sh` 到测试目录；热备份一致性失败就停下，问你是否自己用 `--stop` 再备份。
- 只在**副本**里清空会话（`sessions.json`）和已知设备（`users.json` 每个账户的 `devices`），只输出条数；账户密码不变。
- 新 compose 项目 `/volume1/docker/nocturne-v2test/`，端口只绑 `<内网IP>:8089:8080`，PUID/PGID 取自生产容器，登录保持开启，不挂 docker.sock；不改生产 compose、反向代理、Cloudflare、路由器。
- 启动后检查 `/api/health`、容器健康、日志（脱敏）、挂载只指向测试目录、图标 / 壁纸 / 配置数量、生产 data 前后 sha256 清单与配置文件修改时间、生产容器未被重启；写报告 `v2test-report-<时间>.txt`（不含秘密，可以直接贴回）。

**打开测试站：必须换一个主机名 + 单独的浏览器会话。** 两个版本的 cookie 名相同（`nocturne_sid` / `nocturne_dev`），而 cookie 不按端口区分：在同一主机名下打开 8089 会覆盖 8088 的登录和「已知设备」。生产站用 IP 打开的，测试站就用 `http://<NAS主机名>.local:8089`（反之用 IP），并且在 **Safari 无痕窗口**里打开。脚本会打印推荐网址。本套件已设置 `NOCTURNE_COOKIE_PREFIX=nocturne_v2test_`，核对 compose 和登录响应确实使用该前缀；生产默认 Cookie 名保持不变。仍使用独立浏览器会话，避免旧套件混用。

**步骤**

1. 把套件放到 NAS（仓库是私有的：从我这里拿 `v2test-kit.tar.gz` 和它的 `.sha256`，或在电脑上 `git archive` 后复制过去），解压后核对：`sha256sum -c SHA256SUMS`。
2. 预检（不做任何改动）：`sudo sh tools/v2test/deploy.sh --dry-run`
3. 部署：`sudo sh tools/v2test/deploy.sh`（看完计划输入 `y`）。
4. 在 Safari 无痕窗口打开打印的网址，用生产账户密码登录，按第 1–5 节验收；先改一处配置。
5. 持久化：`sudo sh tools/v2test/check-persist.sh`（只重启 `nocturne-v2test`，核对配置 sha256 与 `/api/health`）。
6. 把两份 `/volume1/docker/nocturne-v2test/v2test-report-*.txt` 贴回给我。
7. 结束后：`sudo sh tools/v2test/teardown.sh`（确认后只删测试容器和测试目录；`--keep-backups` 保留备份）。
8. 测试容器里的修改不会回到生产版本。验收全部通过后，再按已获批准的目标版本操作手册和 `engineering-rollback.md` 对正式容器升级（届时另行确认）。
