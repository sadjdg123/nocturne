> 约定：下文「夜曲地址」指测试部署的地址（见第 6 节的建议方案，例如 `http://NAS的IP:8089`）。

## 6. 建议的测试部署方案（仅为提议，等待用户批准后才执行）

> **状态：提议，未执行。** 我不会在 NAS 上做任何操作；以下步骤需要你确认后由你执行（或批准我执行）。

目的：在**不影响正在使用的 V1.1**（`ghcr.io/sadjdg123/nocturne:sha-3e6da3c`，端口 8088，数据 `/volume1/docker/nocturne/data`）的前提下试用 V2 RC。

1. **备份**（第 4.0 步）：`sudo sh tools/backup.sh --stop nocturne -o /volume1/backup/nocturne /volume1/docker/nocturne/data`，并 `verify-backup.sh` 校验。
2. **复制一份数据**给测试容器（用恢复脚本，顺便演练恢复）：
   `sudo sh tools/restore.sh /volume1/backup/nocturne/nocturne-backup-<时间>.tar.gz /volume1/docker/nocturne-v2test/data`
3. 新建项目 `nocturne-v2test`（`/volume1/docker/nocturne-v2test/docker-compose.yml`）：

   ```yaml
   services:
     nocturne-v2test:
       image: ghcr.io/sadjdg123/nocturne:sha-<RC 提交>@sha256:<RC digest>   # 见 rc 报告第 1 节
       container_name: nocturne-v2test
       restart: unless-stopped
       ports:
         - "8089:8080"        # 另一个端口，与 V1.1 的 8088 并存
       environment:
         - TZ=Asia/Shanghai
         - PUID=1026          # 与 V1.1 容器相同
         - PGID=100
         # - TRUSTED_PROXY_CIDRS=…   # 第 5 节确认后再填
       volumes:
         - ./data:/data       # 是第 2 步的副本，不是 V1.1 正在用的 data
   ```
4. 启动后按第 1–5 节逐项验收；反向代理为测试单独建一个子域名（如 `v2test.你的域名`）指向 8089。
5. 注意：两个容器的数据是**分开的**，在测试容器里做的修改不会回到 V1.1；测试结束后可以直接删除 `nocturne-v2test` 项目和目录。
6. 验收全部通过后，再按 `docs/v2.0-upgrade-rollback.md` 对正式容器升级（届时另行确认）。
