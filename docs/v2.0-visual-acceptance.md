# 夜曲 Nocturne V2.0 · 视觉验收报告（阶段 3 · 手机底栏修复）

> 分支 `v2`。没有合并 `main`，没有部署 NAS。回滚镜像仍是 `ghcr.io/sadjdg123/nocturne:sha-3e6da3c`（V1.1）。
> 本轮只修手机（<768px）新版外观的悬浮底栏（Dock）：空间名被遮住、正文从底栏后面透出来；顺带减轻了手机切换空间的长任务。经典外观、桌面 / 平板布局、数据模型、同步都没有改动。

## 1. 问题与根因

| 问题（阶段 3 截图 `m390-s-nas.png`） | 根因 |
| --- | --- |
| 「全部」看不见，只剩一个「23」 | 4 个分段（名称 + 数量）在 390 宽只有 248px 的滚动区里放不下，载入时为了让 NAS 可见把 track 滚到了最右；两端的渐隐是**常驻**的，看不出哪一侧还有内容，被裁掉一半的「全部 23」只剩数字。另外 `.x-spaces` 在经典样式里有 `left:50%` / `bottom:…`，一旦给它 `position:relative` 就会整块偏出底栏（本轮修复时发现并抵消）。 |
| 「Backup…example」等正文从底栏透出 | 底栏底色只有 `rgba(14,19,31,.74)`，主要靠 `backdrop-filter` 模糊；模糊之后的浅色文字仍然能读出来，亮色壁纸更明显。编辑模式下底栏还留在编辑栏后面，空间名会从编辑栏透出。 |

## 2. 做了什么

**布局（`public/midnight.css` 4c 段、`public/midnight.js`、`public/index.html` 切换器）**

- 底栏是三个独立的 flex 子项：`快速打开`（44×48）｜空间滚动区 `.x-spaces`（`flex:1; min-width:0; overflow:clip; position:relative; inset:auto`）｜`更多`（44×48），间隔 6px。按钮和滚动区在几何上不相交，名称不可能被按钮压住；`overflow:clip` 让 `focus()` / 程序滚动也滚不动这个容器。
- 横向滚动发生在里面的 `.x-sp-track`（`scroll-padding-inline:14px`、`scroll-snap: x proximity`、`overscroll-behavior-x: contain`）。渐隐只作用在 track 自己身上，并且**只在那一侧确实有被藏住的分段时**才出现（`is-ovl` / `is-ovr`，滚动时更新）。
- 数量只显示在当前空间上（其余分段的数量仍在 `aria-label` 里）：375 / 390 / 430 宽 4 个空间全部直接可见，不用横滑；当前空间多了一个数字，也更好认。
- 当前空间自动进入可见区：`App.spaces.reveal()` 只改 `track.scrollLeft`（不用 `scrollIntoView`，页面不会纵向跳）。已经完整可见就不动（nearest），否则居中；名称比可视区还宽时左对齐。载入、切换、改变宽度 / 旋转、字体载入完成时都会执行。
- 长名称：分段最宽 10.5em，名称 7.5em 后省略号；完整名称在 `title` 和 `aria-label`（「名称，N 个项目」）。
- 指示条仍在 track 里随内容滚动；切换后在下一帧重新对齐当前分段。

**背景隔离**

- 底栏材质：`linear-gradient(rgba(27,37,58,.93) → rgba(13,18,30,.96))` 打底（模糊失效或遇到亮色壁纸也不透字）+ `blur(18px) saturate(130%)` + 1px 纸色细描边（.13）+ 顶部内高光 + 底部内阴影 + 外侧 1px 暗描边。仍是 Midnight 的午夜蓝材质，只是更实。
- `.mn-dockscrim`：固定在视口底部、高 = 栏高 + 50px + 安全区的局部暗化渐变（0 → .55 → .82），`aria-hidden`、`pointer-events:none`、在底栏之下（z 19 / 20）；软键盘弹出时与底栏一起收起；经典外观和桌面不出现。正文底部留白相应从 +20px 加到 +36px，滚到底时最后一张卡仍完全在栏顶之上。
- 编辑栏用同样的材质；编辑模式下底栏 `display:none`（被编辑栏替换，而不是叠在后面）。

**性能（可选项，小改动）**：切换空间时，把指示条定位和横向滚动的布局读取挪到下一帧；入场动画重启只做样式计算（不读 `offsetWidth`）；「已滚过分组顶部才回顶」的位置读取也挪到下一帧。同步路径少了几次强制整页布局。没有重构。

样式 / 脚本版本号 `midnight.css?v=2`、`midnight.js?v=2`（静态资源缓存 1 天，必须换号）。

## 7. 性能（手机 390，CPU 4× 节流，同一脚本 6 次切换）

| | 同步耗时 | 长任务 | 最大帧间隔 |
| --- | --- | --- | --- |
| 修复前 | 76–137 ms | 79–139 ms（6 次都有） | 83–167 ms |
| 修复后 | 37–91 ms | 68–93 ms（6 次里 5 次；1 次无长任务） | 67–117 ms |

阶段 3 报告里的 142 ms 是另一次运行的单次值；同一环境前后对比：长任务中位数约 98 ms →（有长任务的 5 次）85 ms，另有 1 次降到 50 ms 以下；同步耗时中位数约 95 → 75 ms。无 GPU 的软件合成比真机悲观。剩下的主要是切换本身的同步重画（分组 DOM）与第一帧光栅化，要再降需要动渲染方式，本轮不做。

## 9. 未验证

- **iPhone / iPad Safari、Mac Safari**：只在 Chromium（Linux arm64 headless）里验证；`overflow: clip`（Safari 16+）、`backdrop-filter`、`env(safe-area-inset-*)`、滚动吸附在 WebKit 上的实际效果未看过。旧 Safari 不认 `clip` 时退回 `overflow: hidden`。
- **真实软键盘**：只用改写 `visualViewport.height` + 示意块模拟，没有真机 iOS / Android 键盘。
- **添加到主屏幕（standalone）模式**：未验证安全区与底栏位置。
- **HTTPS 反向代理**后的行为、缓存头与版本号刷新：未验证。
- **NAS 真机**（群晖 Docker）：未部署、未验证；性能数据来自无 GPU 的软件合成。
- 真实手指的滑动惯性、吸附手感、半可见分段的误触率：只有几何测量，没有真人试用。
