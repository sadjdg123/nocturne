## 1. 实际修改与故障行为

生产代码只修改 `server.js`，新增关键文件读取与写入前复核；没有改动前端、空间数据结构、Cookie 名称、Dockerfile、生产发布工作流或工具。

| 场景 | 修复后行为 |
| --- | --- |
| 认证模式下 users.json / sessions.json 损坏、不可读或记录结构异常 | 在 listen、快照、迁移、残留清理之前停止启动，退出码 2；保留原文件，不开放 setup |
| users.json 缺失或合法空账户列表，但有会话、配置、备份、旁路、素材或固定升级快照 | 判定为孤立既有数据，禁止再次初始化管理员 |
| 运行中认证文件损坏、删除、不可读或被外部替换 | 锁存存储故障，认证及相关 API 返回 503；定时会话落盘和 SIGTERM 关闭也不能用旧内存覆盖文件 |
| 单用户配置损坏或不可读 | 阻断该用户 GET / PUT / force / restore / stash 和相关上传入口；启动迁移、旁路自愈、空间找回不修写坏配置；其他正常用户仍可使用 |
| 读过的配置消失；重启时配置缺失但有环形/旧单槽备份、旁路或固定升级快照 | 不返回空配置，不接受 baseVersion=0 的首次覆盖 |
| 原先缓存命中，但配置被同大小、同 mtime 的损坏内容替换 | 每次严格读取关键文件，拒绝使用旧缓存隐瞒异常 |
| 检查文件存在后，读取抛 ENOENT | 视为读取故障，不能当作首次创建 |
| 写临时文件期间目标损坏 | 在写入开始和 rename 前复核；返回 503，保留损坏目标，只清理这次创建的临时文件 |
| 运行中确认损坏后，外部把文件改回正常 | 本进程仍阻断，修复后需受控重启重新校验，避免自动重试覆盖 |

健康检查出现关键存储故障时返回 HTTP 503、`ok:false`。匿名响应只显示存储状态，故障细节只向仍可认证的管理员展示；认证文件故障时不能再认证管理员。普通相关 API 使用 `code:storage_unavailable` 和原有错误处理通道。日志不输出 JSON 原文、凭据或内部文件指纹。

无认证模式仍使用原来的 default 用户，并保留正常旧账户的既有迁移/探测名单；坏认证文件不参与认证，关闭时也不被重写。真正空的新站点、没有任何历史配置证据的新账户仍可初始化和首次保存。固定升级快照中的同名旧账户与新建账户若有不同且有效的原有 `created` 字段，不阻止新账户首次保存；身份无法明确判定时保守阻断。

## 4. 兼容影响

新增双向兼容测试逐个运行 RC.1、RC.2、RC.3、RC.4 的真实历史 server：旧版创建账户/会话并保存配置，修复版启动后读取并保存，再切回对应旧版读取。验证默认 `nocturne_sid`、`nocturne_dev`、未知配置字段、空间空数组及数据一致性。

没有新增磁盘字段或格式版本，没有批量改写正常账户/会话/配置。RC.1 旁路向 fmt:2 的自愈属于 RC.4 已有行为，兼容测试允许此旁路变化并检查主数据字节不变。读取的最低结构校验允许原有可选字段缺省，不重新套用新输入 URL 白名单；既有旧 URL 及空间容错仍由原逻辑处理。

双向兼容证明旧版可以读取正常修复版数据；回滚到旧版会失去本次新增的损坏保护，不能把数据兼容理解为旧版同样安全。

有意改变的边界：以前“坏文件当空文件”以及“有旧数据但无账户时重新 setup”的路径现在拒绝。关键文件若是符号链接或目录，也会拒绝，要求普通文件。运行中手工替换认证文件即使内容合法，也需要停服务后操作并重启；当前进程不接受来源不明的新认证状态。

## 5. 剩余风险与下一步

1. 本项保护读取及避免覆盖坏文件，尚未解决一般写失败时的账户/会话内存回滚、跨文件事务、Cookie 提交时机和 SIGKILL 中断恢复。这些仍是 P1-2，需要按小步骤单独验证，不应从本报告推断认证事务已经修好。
2. 关键配置取消 mtime 缓存，认证读写增加磁盘读取及摘要复核，存在额外 I/O；没有进行 NAS 性能或真实磁盘故障测试。
3. 数据目录继续要求单实例写入。rename 前复核不是跨进程原子 compare-and-swap，不能消除外部写入者恰好在最后检查与替换之间改文件的竞争；也不证明断电后的文件系统耐久性。
4. 若重启前把全部认证文件及全部历史证据一并删除，现有格式无法区分“全新空目录”和“历史数据被完全抹去”。本项不增加格式或安装身份文件。
5. 结构合法但内容被人为改成错误配置，不一定能被最低结构校验识别。旁路、备份及恢复工具的完整性仍按后续工作包处理；本次不自动修复、隔离或恢复原文件。
6. 存储故障会锁存，修复后须受控重启。应先停服务、保留目录副本、核查或恢复关键文件，再启动验证；P1-1 没有新增维护 UI 或自动解除功能。
