# V2.1.2 · 迁移同步保护

基于现有 v2 / V2.1.1 最小修复，吸收外部审查确认有效的迁移竞态回归，不合并旧 main 修复分支。

保存包含旧 data URL 图标或由服务端规范化空间时，后续读取只在本机仍对应已接受快照、版本未变化、没有待解决冲突时采用结果。等待期间的新标题、项目、图标及空间修改继续保留，并以正确 baseVersion 和独立 opId 重推。晚到的旧响应不能回退已确认版本。

规范化读取有 10 秒上限，支持 AbortController 时同时取消请求；失败、超时或不支持取消均不得无限阻塞新保存。正常迁移仍取得文件引用，设备本地的内外网模式和最近使用不变。

不修改 server.js、认证事务、数据格式、空间语义、UI 或公网 Secure Cookie 策略。nocturne.js 缓存 URL 从 v9 升到 v10；V2.1.1 已纳入发布资源基线。

## 验证与发布

新增 11 项同步测试：在原 V2.1.1 上 9 项失败、2 项控制用例通过；修复后 11/11。包含受控 PUT/GET 延迟、读取失败、挂起、超时取消、晚到响应及 V2 空间兼容。完整回归、镜像和 digest 在现有 Actions 发布完成后登记。

旧版源码反证、本地专项和 GitHub CI 日志保留于开发机 audit-evidence/v2.1.2。用户自行固定镜像升级；继续保留 NOCTURNE_SECURE_COOKIE_HOSTS=jingbo.men 和现有 Bridge/Access 配置，不需要迁移数据。本轮不操作 NAS 或 Cloudflare。
