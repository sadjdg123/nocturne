## 2. 修复：nocturne.js 的 `?v=` 没跟着内容变

**问题**：静态脚本缓存 `max-age=86400, must-revalidate`，浏览器在一天内会直接用缓存，不看服务器有没有更新，靠 `index.html`（`no-store`）里的 `?v=` 换 URL 才能拿到新文件。
RC.1、RC.2、RC.3 的 `index.html` 都引用 `nocturne.js?v=8`，而 `nocturne.js` 的内容在 RC.2、RC.3 各改过一次。所以从 RC.1 / RC.2 升级到 RC.3 的浏览器，最长一天内可能还在用旧的 `nocturne.js`（比如收不到 RC.3 的管理员旁路异常提示）。

**核对范围**（用工具从四个已发布提交的远端树读取，按内容比对）：`index.html` 里的全部 `src` / `href` / `url()`（脚本、样式、图标、manifest、`<img>`），样式表里的 `url()`（`fonts/fonts.css` → 7 个 woff2），`site.webmanifest` 的图标。运行时拼接的地址只有 `api/wallpaper?v=<上传时间>`（服务器按上传时间区分，不属于静态资源）。

| 资源 | 现在的 URL | 和 V1.1 / RC.1 / RC.2 / RC.3 比 | 处理 |
|------|-----------|---------------------------------|------|
| `nocturne.js` | `?v=8` → **`?v=9`** | 与 V1.1（`?v=4`）、RC.1、RC.2（都是 `?v=8`）内容不同 | **改 `?v=9`** |
| `cmdrank.js` | `?v=3` | 与 RC.1–RC.3 相同；与 V1.1 不同但 V1.1 用的是 `?v=2` | 不动 |
| `midnight.css` `?v=3`、`midnight.js` `?v=2`、`spaces.js` `?v=3`、`status.js` `?v=1` | — | V2 新增，与 RC.1–RC.3 相同 | 不动 |
| `urlcheck.js` `?v=3`、`netmode.js` `?v=1`、`Sortable.min.js`、`fonts/fonts.css` 和 7 个 woff2、图标、壁纸、`site.webmanifest` | — | 与四个版本全部相同 | 不动 |

只改了 `public/index.html` 的这一个 `?v=`（另外 `tools/e2e/https_proxy.py` 的模拟部署跟着从 `v=8/9` 改成 `v=9/10`）。用户升级到 RC.4 后，浏览器会立刻拿到新的 `nocturne.js`。

## 3. 测试：`test/cache-bust.test.js`

- 新规则：**对每个已发布版本，现在的 URL（路径 + `?v=`）如果和该版本用过的一样，内容必须逐字节相同**；内容变了就必须换 `?v=`。覆盖 V1.1、RC.1、RC.2、RC.3（每个版本一个用例），没有 `?v=` 的资源（字体、图标、manifest）也在内。
- 清单 `test/fixtures/released-assets.json`：每个版本当时浏览器会缓存的 URL → `{path, v, blob, sha256}`，由 `tools/gen-released-assets.js` 从 GitHub 远端提交生成（`--check` 只核对、不写）。测试本身不依赖 git，任何环境都能跑。
- CI 是完整历史检出（`fetch-depth: 0`），所以多加一项：按提交 `git rev-parse <提交>:public/<路径>` 核对清单本身。CI 里四个提交都必须找得到，否则失败；本地沙盒（远端提交 SHA 与本地不同）只核对 blob。
- URL 提取逻辑放在 `test/asset-refs.js`，测试和生成脚本共用，口径一致。缓存头测试改成从 `index.html` 读 `nocturne.js` 的地址，不再写死 `?v=8`。
- **修复前会失败**：在 RC.3 代码（`?v=8`）上，`same URL as RC.1 (2ee0983)` 和 `same URL as RC.2 (3d5beaf)` 两项失败，信息是 `content changed since RC.1 but URL unchanged …: nocturne.js?v=8`（8 项里 6 过 2 失败）。修复后 8 / 8 通过。
- 全部测试：本地 210 / 210（41 个文件，204 → 210，新增 6 项），CI 210 / 210，没有跳过的用例。

## 4. 文档：健康检查地址

生产端口绑定在 `192.168.50.141:8088`（compose `ports` 写了 IP），在 NAS 上用 `127.0.0.1:8088` / `localhost:8088` 是连不上的。下面这些文档的健康检查已统一改为：

```sh
NAS_IP=${NAS_IP:-192.168.50.141}      # 以 sudo docker port nocturne 8080/tcp 的输出为准
curl -s "http://$NAS_IP:8088/api/health"
```

改动范围：`docs/v2.0-upgrade-rc.md`（文首说明、第 4 / 5 / 6 节）、`docs/v2.0-upgrade-rollback.md`（文首说明、第 1 / 2 节）、`README.md`（部署一节的说明、「版本与回滚」各步骤，DSM 反代 `localhost:8088` 一行注明只在端口没绑定具体 IP 时可用）、`docs/HANDOFF-CODEX.md`、`tools/v2test/README.md`。
`docs`、`README.md`、`tools` 里已经没有把 `127.0.0.1:8088` / `localhost:8088` 当成可用地址的写法。剩下的 `127.0.0.1` / `localhost` 都在 `tools/e2e/*`、`tools/stage*` 里，是沙盒脚本连自己临时起的测试服务器，跟 NAS 无关；另外还有 README 里的本地开发地址 `localhost:8080` 和主机名示例。

## 7. 还没解决的风险

- **v2test 套件的 busybox 自测是 39 / 50（11 项失败）**：沙盒里的 busybox 静态版会优先用自己内置的 `ip` / `hostname`，绕过了测试放的假命令。RC.2、RC.3 代码上也一样，跟夜曲代码无关；dash 轮次是 50 / 50（RC.3 时）。这次 `tools/v2test/lib.sh` 换成了 RC.4 镜像，但当前沙盒没有 `ip` 命令，也没有 sudo，加不了回环别名，套件自测会直接 SKIP，**RC.4 没有重新跑套件自测**。
- **真机项目还要人工验收**：Safari（iPhone / Mac）、真实 HTTPS 反代、群晖实机（`docs/v2.0-manual-acceptance.md`）。
- **RC.1 → V1.1 → RC.3 / RC.4 这条路不会自动找回空间**：RC.1 写的旧格式旁路不会被使用，要手动在 设置 → 账户 →「恢复较早的版本」里恢复。
- 清单只记录到 RC.3。以后再发版（包括把 RC.4 加进去）要在 `tools/gen-released-assets.js` 的 `RELEASES` 里加一行，重新生成清单，并把测试里的版本列表一起改掉（见交接文档）。
