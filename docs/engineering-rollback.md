# 发布前工程回滚与恢复边界

本文适用于已发布的 RC.5 可靠性修复版，固定镜像见 `v2.0-rc5-report.md`。NAS 升级和生产数据操作由用户自行执行；本轮开发与发布没有执行以下部署操作。

## 升级前基准

记录完整源码提交、镜像 `标签@digest`、DATA_DIR、挂载、PUID/PGID 和唯一写入实例。手工停止写入实例并确认退出；保持停写，按 `stopped-backup.md` 生成完整归档与侧车，再用 `verify-backup.sh` 校验，在独立目录恢复和启动修复版核对账户、配置、空间及资产。热备份不能替代该基准。不要排除快照环、认证事务、退休目录或 `.auth-cleanup.<UUID>.json`。

归档含认证秘密；只交付脱敏日志，归档保留在受控位置。Linux 工程演练使用的全部数据为临时夹具，没有生产数据。

## 异常重启

修复版在加载账户、迁移与监听前恢复 `.auth-transaction`：COMMITTED 前撤销，标记后重做；状态未知或校验/磁盘 I/O 失败停止启动并保留现场。不能把状态错误当作清理待办而继续发 Cookie。

已核验退休材料 `.auth-done.<UUID>.tmp` 只能按其外部清理凭据核验剩余内容为原清单子集，再重复清理。符号链接、未知目录、额外文件及内容替换均失败关闭。没有凭据的旧版部分删除材料不能自动推断来源，须保留并独立审查。不要手工删除活动记录、DONE、COMMITTED 或凭据。

SIGKILL 重启演练证明进程中断恢复逻辑，不等于断电、硬盘缓存或 DSM 文件系统耐久性证明。修复版仍要求单实例写入及有效的 fsync/rename 语义。

## 回滚至 RC.1–RC.4

正常主数据格式、默认 Cookie 名和空间语义保持兼容。旧 RC 不理解认证事务恢复协议：若存在活动事务，必须先让修复版恢复、验证唯一密码/会话状态与配置、确认健康，再正常停止。不能在半完成状态直接改镜像启动旧 RC。

修复版无法恢复时：保留故障目录及完整备份，恢复一份已校验的升级前停写备份至独立目录核对，之后再由用户批准切换。不要覆盖或删除故障现场。回滚期间旧 RC 不具备新的损坏保护和跨文件事务保护。

## 离线恢复工具中断

`restore.sh --force` 保留原目录；`<目标>.restore-state` 绑定同父目录旧/新材料及 inode。保持服务停止，重跑相同命令按 `restore-recovery.md` 恢复：退出 0 表示验证后新目录已安装；退出 4 表示旧目录已恢复，备份尚未应用，核查后重试。身份冲突、链接或记录缺失时不猜测，不改名搬走唯一材料。

BusyBox 的 `ls -di` 可能有前导空格，修复版会先规范化再验证数字 inode；真实 Alpine BusyBox 的归档校验、离线恢复和含中断认证事务的启动已验证。DSM 宿主具体工具版本仍需用户批准的隔离实机验收。

## 发布工程的撤回

本轮生产 `.github/workflows/docker.yml` 未变；新增工程 workflow 无发布权限，不需要撤回 GHCR 标签。防覆盖 helper 尚未启用；正式切换时需单独 review、共享锁与所有写入者权限收敛。禁止通过重推已发布标签完成回滚，必须使用已验证 digest。
