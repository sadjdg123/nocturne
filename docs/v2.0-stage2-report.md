# 夜曲 Nocturne V2.0 · 阶段 2 报告：空间管理与跨端交互

> 范围：在 **V1.1 现有视觉语言** 里把场景空间做成可用的功能（切换器、管理空间、空状态、空间内编辑、跨空间搜索、向前兼容、原型安全、纯静态模式）。
> 完整的 Midnight 视觉系统属于阶段 3：本阶段没有改版首页，切换器 / 管理面板的 DOM 与逻辑留给阶段 3 只换样式（`.x-spaces` / `.x-sp` / `.x-spm*` 类名稳定）。
> 分支 `v2`。未改 `main`，未部署 NAS。

## 1. 行为定义

### 1.1 空间切换器

| 项 | 定义 |
| --- | --- |
| 位置 | 桌面 / 平板（≥768px）：搜索栏与引擎下方一行轻量导航（≥900px 两栏布局里横跨两栏）。手机（<768px）：固定在底部快捷栏正上方的拇指区横滑条（宽度同快捷栏，`env(safe-area-inset-bottom)` 计入），正文底部留白相应加大，toast 上移 |
| 内容 | 「全部」永远第一个、不可删除；之后按 `data.spaces` 顺序；每个按钮显示名称 + 该空间的项目数；末尾一个「管理空间」按钮 |
| 何时显示 | 只有存在自定义空间时（`body.has-spaces`）。没有空间的账户首页与 V1.1 完全一样；「管理空间」入口在 ⋯ 菜单与命令面板 `>` 操作里 |
| 切换的效果 | **只**改本机选择 `localStorage["nocturne.space:<账户>"]`（纯静态页为 `~local`）并重新渲染：展示范围 + 系统状态卡（标题「系统状态 · 空间名」、在线 x / y 只统计该范围的图标项目）+ 离线列表。**不调用 commit、不改 state、不发请求、不升版本**（测试断言 state 字节相同、无 PUT、版本不变） |
| 回落 | 记住的空间不存在（被删 / 别的账户 / 乱写）→「全部」 |
| 键盘 | 切换器是 `role="toolbar"`，roving tabindex（只有当前空间可 Tab 到），←/→/↑/↓ 循环移动焦点、Home / End，Enter / 空格激活（原生 button），当前项 `aria-current="true"`，按钮 `aria-label` 带项目数；`Alt+1` =「全部」、`Alt+2…9` = 第 1…8 个自定义空间（输入框里 / 浮层打开时不响应） |
| 与长按编辑的关系 | 切换器在 `#x-groups` 之外，长按 / 拖动只在分组区生效；拖动中（`body.dragging`）切换器 `pointer-events:none`，放手不会误切；编辑模式里可以切换空间（在空间里编辑） |
| 网络 / 状态 | 网络三态（自动 / 内网 / 外网）和服务状态检测与空间无关：切换不触发重新检测、不改网络模式、已有的检测结果不重置；改网络模式也不改空间（测试） |

### 1.2 管理空间

底部抽屉（手机）/ 居中对话框（≥768px），`role="dialog" aria-modal="true"`，Esc 关闭（有删除确认时先取消确认），Tab 焦点留在面板内，关闭后焦点回到触发按钮。

- **新建**：名称输入 +「日常 / 娱乐 / NAS」模板按钮——模板**只填名称**，不按名称猜测、不自动放入任何分组；新建后自动切到新空间并展开它，让用户勾选分组。第一次新建时写 `data.spacesVersion = 1`。
- **改名**：展开后的名称表单。
- **排序**：每行 ↑ / ↓ 按钮（第一个不能再上移，「全部」始终在最前）+ 拖动手柄（SortableJS，已有依赖）。
- **删除**：先显示确认「只删除这个空间，分组、项目、图标和壁纸都不会删」，确认后只删这条空间记录；toast 带「撤销」。删掉当前空间 → 回到「全部」。
- **勾选分组**（`groupIds`，整组：以后加进这些分组的项目也会出现），每个分组显示项目数与「也在 N 个其他空间」。
- **单独添加项目**（`itemIds`，可选，折叠区）：已整组包含的分组里的项目显示为已勾选且禁用。
- **校验提示**与服务器同一套规则（`spaces.js nameProblem / MAX_SPACES`）：不能为空、≤24 个字（按码点，计数显示 `n/24`）、不区分大小写不重名、「全部」是保留名称、最多 24 个空间（满了输入框禁用并提示）。不合法时不 commit。
- **全部修改走 `App.commit`**：每次一个撤销步骤；同步走现有链路（caps、opId、409 冲突面板、400 `bad_spaces` 停止重推）。管理面板开着时发生 409，冲突面板显示在它上面，键盘也归冲突面板；选「使用服务器版」后面板按新状态重画。

### 1.3 空空间

当前空间没有任何可见内容（没选分组，或引用的分组 / 项目都被删了、引用已被清掉）→ 分组区显示「「X」里还没有内容」+ 说明（空间只引用、不复制）+ 琥珀按钮「选择分组」，直接打开管理空间并展开这个空间。编辑模式下照常有「＋ 添加分组」。

### 1.4 空间里的编辑（统一全局顺序）

| 操作（在某个自定义空间里） | 结果 |
| --- | --- |
| 添加项目到本空间显示的分组 | 加进那个分组；整组在空间里 → 直接出现，不改空间 |
| 添加项目时选了**不在本空间的分组**（含只因单独项目而部分显示的分组） | 项目存进所选分组（唯一实体），并**自动单独加入本空间**（`itemIds`），保存后仍在眼前；toast 说明 |
| 添加时选「新分组…」/ 编辑模式「＋ 分组」 | 新分组**整组**加入本空间（`groupIds`） |
| 移到分组（移到不在本空间的分组） | 自动单独加入本空间，项目不会凭空消失；toast「仍显示在本空间」 |
| 复制一个只靠单独引用出现的项目 | 副本（新 id）也单独加入本空间（否则一复制就看不见）。在「全部」里复制不改任何空间（与阶段 1 定义一致） |
| 删除项目 / 分组 | 全局删除（菜单写明「删除项目（所有空间）」「删除分组（所有空间）」），悬空引用在同一次 commit 里清掉，撤销一起恢复 |
| 从「X」移除（分组或单独项目） | 只改空间关系，分组 / 项目都还在；可撤销 |
| 拖动排序 | **统一全局顺序**（`spaces.reorder`）：只重排看得见的这些彼此之间的先后——看得见的分组依次填回它们在 `data.groups` 里原来占的位置，看不见的分组不动；部分显示的分组里看不见的项目跟着它前面那个看得见的项目走；跨分组拖入插在拖到的位置；任何项目都不会丢。在「全部」里等同 V1.1 的整体重排。先在浅拷贝上试，没有实际变化不提交 |
| 撤销 | 照旧（空间关系与分组 / 项目在同一个 commit 里） |

在「全部」里所有编辑行为与 V1.1 相同，不会改任何空间。

### 1.5 搜索与 ⌘K 命令面板

- 命令面板**永远搜全部项目**（与当前空间无关），每行标出「服务 · 分组名」；别名、分层排序（cmdrank）、备用地址行、`A.url` 地址选择、`>` 操作模式、刷新状态都不变。
- 新增内置操作：「切换到空间：X」（含「全部」，描述为「当前空间」或项目数）和「管理空间」。它们只是操作，排在服务、分组结果**之后**；空输入时的建议列表不变（不列空间）。
- 打开一个不在当前空间（屏幕上没有图标）的项目：照样按 `A.url` 打开、照样记入「最近使用」（`App.trackRecent`），不切换空间。
- 跳到一个不在当前空间的分组：先切回「全部」（toast 说明）再定位、聚焦第一个图标。
- 首页搜索引擎栏与空间无关。⋯ 菜单 / 命令面板「添加项目」、粘贴网址新建默认用当前空间里的第一个图标分组。

### 1.6 向前兼容（用户决定）

目标：较旧的 V2 客户端不能悄悄丢掉较新版本加的空间字段。

- **扩展字段**：空间里不认识的键。字段名 `/^[A-Za-z][A-Za-z0-9_]{0,31}$/`，不能是 `Object.prototype` 上的名字，不能用项目字段名（`items/groups/spaces/settings/recent/title/url/lan/wan/icon/aliases/desc`，任何一层都不行——空间不能变成第二套项目集合，也不能借此绕过 URL 白名单）；值只允许 null / 布尔 / 有限数字 / 字符串（≤1024 字、无控制字符、不能是 `javascript:` `data:` `vbscript:` `file:` `blob:` 地址）/ 数组（≤64）/ 普通对象（≤32 键，键 `/^[A-Za-z0-9_-]{1,32}$/`），嵌套 ≤4 层；每个空间 ≤16 个扩展字段、合计 ≤4096 字节。
- **前端** `normalize()`：认识的字段照旧清洗；合法扩展字段**原样保留（值与键顺序）**；畸形扩展字段丢掉；超出预算的按顺序丢掉。commit / 撤销 / 导出 / 导入（导入先 `check(lenient)`）都带着它们。
- **`data.spacesVersion`**（1–999 整数，可选）：写过这份配置的最高空间 schema。本版本 SCHEMA = 1；`add()` 只升不降。
- **前端推送** `caps: ["spaces", "spaces:1"]`。
- **服务端** `check()`：合法扩展字段放行，畸形的仍 400 `bad_spaces`；`reconcileSpaces()` 按 caps 判断客户端 schema 版本 N（只有 `"spaces"` = 1，没有 = V1.1）：
  - N ≤ 服务器 SCHEMA：同 id 的空间里，服务器上有、客户端**不认识**（`knownKeys(N)` 之外）、请求里又没有的字段 → 原样补回（返回 `spacesRestored`、`migrated:true`，前端会重拉）。客户端认识的字段（如 `theme`）被删视为有意删除，不补。补回会超出预算 → 这个空间不补（不报错）。删掉整个空间不受影响。
  - N > 服务器 SCHEMA（更新的客户端）：完全以它为准。
  - `spacesVersion` 只升不降；V1.1 前端（无 caps）沿用整份空间定义（含扩展字段与 `spacesVersion`）。
- 阶段 1 的白名单测试已相应更新：「未知字段一律 400」改为「畸形 / 保留名 / 原型名扩展字段 400」，合法扩展字段保留（`junk: 1` 保留）。

### 1.7 原型安全

`public/index.html`（状态统计 `all()`、离线列表、命令面板去重 / 最近使用 / 高亮、图标与壁纸失败缓存、事件表）、`cmdrank.js`（最近使用排名、去重）、`nocturne.js`（容器 id 表）改为 `Map` / `Set` / `Object.create(null)`；选择器里的 id 统一 `CSS.escape`（`App.util.sel`）。修正前 `cmdrank.rank` 遇到最近使用里的 `constructor` 会拿到 `Object.prototype.constructor` 当排名（函数），排序错乱。

### 1.8 纯静态模式

没有 `window.NOCTURNE`（`python3 -m http.server` / `file://`）：空间随 commit 存在本机缓存 `yeqv.v1` 里，当前空间存在 `nocturne.space:~local`；不发任何 `/api` 请求；切换器、管理空间、空状态、跨空间搜索、导出导入都可用；没有空间的旧缓存不被改写。

## 5. 已知限制 / 后续

- 切换器在手机上与底部快捷栏叠成两层（约 60px），首屏内容区相应变矮；阶段 3 按设计稿合并为一块底部材质。
- 空间外观（theme / density）本阶段未渲染（阶段 3）。
- 项目数徽标统计所有项目（含链接型），状态卡只统计图标项目——两者口径不同是刻意的。
- 管理面板每次修改都即时 commit（每次一个撤销步骤、一次同步），没有「取消全部」。
