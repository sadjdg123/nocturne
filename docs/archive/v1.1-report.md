## 四、旧前端编辑带别名的项目（专项测试）

做法：用 **新 `server.js`** 加 `PUBLIC_DIR` 指向 `0617b61` 的 `public/`（旧 `index.html` + 旧 `nocturne.js`），在 Chromium 里真实操作。

| 旧前端操作 | 结果 |
| --- | --- |
| 打开编辑表单改描述并保存 | **别名保留**（旧版保存是 `Object.assign(原项目, 表单字段)`，不认识的字段原样留下），服务器 v2 中 `aliases` 不变 |
| 编辑模式「复制」 | 副本带同样的别名 |
| 「移到分组」 | 别名保留 |
| 撤销 | 别名保留 |

结论：**旧前端不会丢别名**，只是看不到、不能编辑、不参与搜索。服务器端无需额外保护。另外：旧版服务器（回滚后）不校验别名，但也原样保存。

## 八、未验证 / 已知限制

- **iPhone Safari 真机：未验证**（软键盘、visualViewport、安全区、点按执行、「添加到主屏幕」全屏模式下的表现只做了 Chromium 模拟）。
- macOS Safari / Windows 实机键盘、真实公网 HTTPS 反代 + 群晖实机：未验证。
- 「自动」只看访问主机名：在家里用公网域名打开会偏向外网（设计如此，可一键改「优先内网」）；通过 Tailscale 访问按外网处理。
- 主页点开后服务打不开（例如 HTTPS 页面跳 HTTP 内网地址被浏览器拦、或当前网络到不了）时，夜曲无法得知，也不会自动换另一个地址——请用备用地址或切换模式。
- 命令面板里备用地址行只跟随「选中」的项目显示（触屏上默认是第一条结果）；其他项目在手机上请用编辑模式的项目菜单。
