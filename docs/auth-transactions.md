# 账户事务与旧 RC 回滚边界

本阶段仍未发布新镜像，版本号和 RC.1–RC.4 的 users.json、sessions.json、配置及空间格式保持不变。

账户操作在原有账户锁内生成副本。`.auth-transaction/RECORD.json` 保存两份认证文件的原字节、新字节和受限删除资产清单，受 SHA-256 完整性校验保护；目录 700、文件 600。记录在修改目标前原子发布并 fsync。删除资产移动至同文件系统的暂存目录，固定升级前快照不删除。删除清单只允许该账户的配置、旧单槽/环形备份、图标、旁路及三个已支持壁纸扩展名；恢复拒绝任意路径、链接、未知资产或内容冲突。资产使用内容指纹，可在隔离目录复制或完整备份恢复后继续恢复。

users/sessions 的候选文件 fsync 和替换后，`COMMITTED` 标记的文件与目录 fsync 是提交点。此前失败回退原字节和资产，内存不变，无成功 Cookie；回退无法完成则返回 503、保留材料、阻断后续操作。标记出现后不得回到旧内存；耐久性结果不明时不发 Cookie、不返回成功，重启按可见标记恢复。已提交操作的清理失败保留材料和诊断，不撤销账户删除或密码修改。登录/设备登记及滑动续期也使用同一协调器；只有持久提交成功后才发送默认或自定义前缀 Cookie。

启动在 loadState、迁移、快照、listen 前恢复：无提交标记撤销，有标记重做。损坏记录或冲突材料停止启动，绝不猜测或删除唯一副本。完成恢复后，退休目录带独立 DONE 状态，清理失败在后续启动重试，不重放过时认证状态。

**回滚旧 RC 前必须满足：** 停止唯一写入实例，完成停写完整备份；若存在 `.auth-transaction`，先用本修复版完成恢复并确认健康，再停机切回旧 RC。旧 RC 不理解恢复记录，不能直接接管强杀后留下的半完成操作。正常提交和正常停机后的主数据仍可由 RC.1–RC.4 读取；旧版也不会获得新版本的事务保护。

本实现不引入数据库、全局认证重写或前端修改。认证持久提交使用同步文件操作，借此避免请求看见两个文件之间的半状态；大账户目录的删除指纹计算会阻塞该 Node 进程，需要后续实际 NAS 性能验收。单实例写入、文件系统 fsync/rename 语义仍是前提；SIGKILL 测试不等于真实断电耐久性证明。
